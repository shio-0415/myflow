# 要件定義書

機能の番号と名前は、このファイルが元になる。工数とスプリントの割り当ては、sprint-plan.md と estimate.md を参照。

## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| プロジェクト名 | MyFlow |
| 解決したい課題 | 締め切りが重なり、何から手をつけていいかわからない |
| コンセプト | 大学生が、締め切りの重なる就活・課題の優先順位を一目で把握し、迷わなくなるアプリ |
| 背景 | 既存のTodoアプリでは時間を自分で入力する必要があり、入力ミスによって優先度を見誤ってしまうことがある。また、優先順位がひと目でわからないため、結局は課題提出のギリギリまで手をつけられないことが多い |
| ターゲットユーザー | アルバイトを掛け持ちしながら、大学の課題・ゼミ・就職活動を両立させている大学3〜4年生 |
| 開発期間 | Week22〜24（10月12日〜30日、3週間・平日15日） |

## 2. ユーザーストーリー（13個）

1. ① 就活中の大学生として、タスクに期限を設定したい。なぜなら締め切りを意識して取り組みたいから。
2. ② 就活中の大学生として、締め切りの近いタスク順に並び替えたい。なぜなら締め切りが重なり、何から手をつけていいかわからないから。
3. ③ 就活中の大学生として、就活用・学校用でタスクを分けて表示したい。なぜなら就活用のタスクが今何個残っているか、パッと数えられるようにしたいから。
4. ④ 就活中の大学生として、タスクを完了にしたい。なぜなら一覧を見たとき、終わったタスクとまだやるタスクの区別がつかないから。
5. ⑤ 就活中の大学生として、タスクを削除できるようにしたい。なぜなら不要なタスクが残ると、本当にやるべきタスクが下にずれて、見つけにくくなるから。
6. ⑥ 就活中の大学生として、タスクの名前をわかりやすく直したい。なぜなら後でタスクを確認したときに、何をすればいいのかがわからないから。
7. ⑦ 就活中の大学生として、完了したタスクを一覧から隠したい。なぜなら目に見えてタスクが減ると、達成感が出てやる気が出るから。
8. ⑧ 就活中の大学生として、かかる時間が短い順に並び替えたい。なぜならタスクが複数ある場合、かかる時間が短いものから片付けることでタスクの量が少なくなり、精神的な負荷が少なくなるから。
9. ⑨ 就活中の大学生として、就活・学校のどちらを優先するか自分で切り替えたい。なぜなら日や週によって、就活を優先すべき時期と学校を優先すべき時期が変わるから。
10. ⑩ 就活中の大学生として、締め切りが近づいたら通知が欲しい。なぜならアプリを開かないうちに気付かず締め切りを過ぎてしまうことがあるから。
11. ⑪ 就活中の大学生として、課題の進み具合と締め切りを見比べたい。なぜなら進み具合によって他のタスクを優先すべきか、それとも余裕があるかを判断したいから。
12. ⑫ 就活中の大学生として、タスクをカレンダーにも表示したい。なぜならタスクの全体量と緊急度を正しく把握したいから。
13. ⑬ 就活中の大学生として、アカウントを作ってログインしたい。なぜなら機種変更してもデータが消えないようにしたいから。

## 3. 機能要件（Must / Should / Could）

| No | 機能 | 分類 |
|---|---|---|
| ① | タスクに期限を設定できる | Must |
| ② | 締め切りの近いタスク順に並び替えられる | Must |
| ③ | 就活用・学校用で分けて表示できる | Must |
| ④ | タスクを完了にできる | Must |
| ⑤ | タスクを削除できる | Must |
| ⑥ | タスクの名前を直せる | Should |
| ⑦ | 完了したタスクを一覧から隠せる | Should |
| ⑧ | 所要時間を入力し、短い順に並び替えられる | Should |
| ⑨ | 就活・学校の優先を切り替えられる | Should |
| ⑩ | 締め切りが近づいたら通知で知らせる | Could |
| ⑪ | 進み具合と締め切りを並べて表示する専用画面 | Could |
| ⑫ | カレンダーにも表示できる | Could |
| ⑬ | アカウントを作ってログインできる | Could |

## 4. 非機能要件

1. PCのブラウザで問題なく動作すること
2. 完了ボタンを押したら10秒以内に反応が返ってくること
3. PCがフリーズしても入力したデータが消えないようにすること
4. （将来、ログイン機能を実装する際には）パスワードを入力してログインしないと、タスクの内容を見られないようにすること

## 6. 制約条件

1. 開発体制は個人で行うこととする
2. 予算は有料のサービスを使わないこととする
3. 開発期間は3週間で開発からデプロイまで完了させることとする
4. 技術スタックは、HTML、CSS、JavaScriptを使い、データの保存先は localStorage とする（詳細は tech-stack.md を参照）
