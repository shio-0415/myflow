# 要件定義書

## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| プロジェクト名 | MyFlow |
| 解決したい課題 | 締め切りが重なり、何から手をつけていいかわからない |
| コンセプト | 大学生が、締め切りの重なる就活・課題の優先順位を一目で把握し、迷わなくなるアプリ |
| 背景 | 既存のTodoアプリは時間を自分で入力する必要があり、入力ミスによって優先度を見誤ってしまうことがある。また、優先順位がひと目でわからないため、結局は課題提出のギリギリまで手をつけられないことが多い |
| ターゲットユーザー | アルバイトを掛け持ちしながら、大学の課題・ゼミ・就職活動を両立させている大学3〜4年生 |
| 開発期間 | Week22〜24（3週間） |

## 2. ユーザーストーリー（10個）

1. 大学生として、タスクに期限を設定したい。なぜなら締め切りを意識して取り組みたいから。
2. 大学生として、完了したタスクは一覧から消せるようにしたい。なぜなら目に見えてタスクを消せると達成感が出てやる気が出るから。
3. 大学生として、締め切りが近い順に並び替えたい。なぜなら並び替えることで優先順位が分かりやすくなるから。
4. 大学生として、かかる時間が短い順に並び替えたい。なぜならタスクが複数ある場合、かかる時間が短いものから片付けることでタスクの量が少なくなり、精神的な負荷が少なくなるから。
5. 大学生として、就活用・学校用でタスクを分けて表示したい。なぜなら就活用のタスクが今何個残っているか、パッと数えられるようにしたいから。
6. 大学生として、就活・学校のどちらを優先するか自分で切り替えたい。なぜなら日や週によって、就活を優先すべき時期と学校を優先すべき時期が変わるから。
7. 大学生として、タスクを編集・削除したい。なぜなら内容の変更や不要になったタスクの整理をしたいから。
8. 大学生として、締め切りが近づいたら通知が欲しい。なぜならアプリを開かないうちに気付かず締め切りを過ぎてしまうことがあるから。
9. 大学生として、課題の進み具合と締め切りを見比べたい。なぜなら進み具合によって他のタスクを優先すべきか、それとも余裕があるかを判断したいから。
10. 大学生として、タスクをカレンダーにも表示したい。なぜならタスクの全体量と緊急度を正しく把握したいから。

## 3. 機能要件（Must/Should/Could）

| No | 機能 | 分類 |
|---|---|---|
| 1 | タスクを作成できる（期限・タグ設定を含む） | Must |
| 2 | 締め切りが近いタスク順に並び替えることができる | Must |
| 3 | 就活用、学校用に分けて表示することができる | Must |
| 4 | タスクを編集できる | Must |
| 5 | タスクを削除できる | Must |
| 6 | 完了したタスクを一覧から消すことができる | Should |
| 7 | 所要時間を入力し、短い順に並び替えることができる | Should |
| 8 | 就活・学校のどちらを優先するか自分で切り替えることができる | Should |
| 9 | 締め切りが近づいたら通知で知らせることができる | Could |
| 10 | 進み具合と締め切りを並べて表示する専用画面 | Could |
| 11 | タスクをカレンダーにも表示することができる | Could |
| 12 | アカウントを作りログインすることができる | Could |

## 4. 非機能要件

1. PCのブラウザで問題なく動作すること
2. 完了ボタンを押したら10秒以内に反応が返ってくること
3. PCがフリーズしても入力したデータが消えないようにすること
4. （将来、ログイン機能を実装する際には）パスワードを入力してログインしないと、タスクの内容を見られないようにすること

## 6. 制約条件

1. 開発体制は個人で行うこととする
2. 予算は有料のサービスを使わないこととする
3. 開発期間は3週間で開発からデプロイまで完了させることとする
4. 技術スタックは、Week1〜17で学んだ範囲と学校で学習したHTML、CSS、JavaScriptの範囲で使用可能なものとする
