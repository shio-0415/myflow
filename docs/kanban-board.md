# カンバンボード設計（GitHub Projects）

機能の番号と名前は requirements.md が元になる。

## ボード

MyFlow開発ボード：https://github.com/users/shio-0415/projects/1/views/1

## 使うカラム

| カラム | 意味 |
|---|---|
| Backlog | まだ着手していないタスク |
| In progress | 作っているところ |
| In review | 作り終えて、実際に動かして確認しているところ |
| Done | 確認して、問題がなかったタスク |

ボードには「Ready」という列も最初からあるが、1人で開発するため、今回は使わない。

## In reviewで確認すること

カードをIn reviewに動かしたら、実際にアプリを動かして、思った通りに動くかを確認する。

| 機能 | 確認すること |
|---|---|
| ①タスクに期限を設定できる | 期限を入力して保存したら、一覧にその期限が表示される |
| ②締め切りの近いタスク順に並び替えられる | 並び替えボタンを押したら、締め切りの近いタスクが上に並ぶ |
| ③就活用・学校用で分けて表示できる | 就活用のタブを選んだら、就活用のタスクだけが表示される |
| ④タスクを完了にできる | 完了ボタンを押したら、そのタスクが完了の表示になる |
| ⑤タスクを削除できる | 削除したタスクが、一覧から消える |
| デプロイ（公開） | 公開したURLを開いて、①〜⑤の機能が動く |

問題がなければDoneに動かす。問題があれば、In progressに戻す。

## 運用ルール

- 各スプリントが始まったら、そのスプリントのカードを動かし始める
- 作業に着手したら「In progress」、作り終えたら「In review」、確認できたら「Done」に動かす
- 1人で開発するため、同時に「In progress」に置くカードは基本1枚とする
- Should（⑥〜⑨）のカードは、Mustと確認作業とデプロイが終わるまで、ボードに並べない
